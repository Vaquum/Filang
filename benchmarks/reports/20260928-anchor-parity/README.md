# Known-indicator parity and family-sweep evidence — 2026-09-28

## What is established

Filang natively reconstructs this **first explicitly bounded cohort** of existing
indicator constructions, matches their numerical values and trading behavior,
and evaluates parameter neighborhoods with full PnL/risk parity. This is not a
claim that all profitable financial features, all TA-Lib functions, or a trillion
numerical programs have been implemented/evaluated.

The cohort has **18 program requests, 15 structurally distinct roots, 44 readouts
and 88 primary/stress metric sets**. It includes six historical fixed rules plus
cash/buy-and-hold, and ten external-reference constructions using **eight of the
158 APIs** in the pinned TA-Lib wrapper. `coverage.json` marks every other API as
not claimed; even a covered API means the listed construction/parameters/data
contract, not all possible configurations or exceptional inputs.

Native source: `621395b8f2af866573bcc89839722a56bf064c50`. Executable SHA-256:
`55b8164785ded0cdd638f915ef32c30fb4decaadbb7252b92950b5fe36bcbece`. TA-Lib wrapper **0.6.8**, bundled C **0.6.4**,
NumPy **2.5.1**. TA-Lib is used only by the external reference. Rust has no
third-party runtime dependencies.

## Repeated end-to-end benchmark

**120,832 full ten-metric evaluations** per run: 252 program requests / 239
structurally distinct roots, radius four, 129 thresholds per direction. Three
fresh-process repetitions for each of five paths; variant order rotated. Apple
M1 Max, 64 GiB, **one native worker**. No CPU pinning; OS file caches were not
flushed. Every metric and exact count in every timed output is compared.

| Matched path | Median whole-process runtime | Min–max | Maximum RSS |
|---|---:|---:|---:|
| TA-Lib cached indicators + NumPy chronological backtests | 27.865454 s | 26.877213–28.050129 s | 131.5 MiB |
| Native independent numerical programs + chronological backtests | 12.676151 s | 12.607992–12.879925 s | 43.2 MiB |
| Native shared numerical graph + chronological backtests | 12.645900 s | 12.642864–12.949631 s | 81.2 MiB |
| Generic family compiler + full-risk threshold sweeps, scalar | 2.292983 s | 2.285464–2.307751 s | 71.7 MiB |
| Same generic family path, NEON | 2.339025 s | 2.317379–2.391817 s | 69.8 MiB |

The measured ratio of the TA-Lib+NumPy application to the NEON family path is
**11.913x**; native independent replay to that path is
**5.419x**. These are whole-workflow comparisons,
**not claims that TA-Lib's standalone C indicator kernels are that much slower**.
The external baseline caches repeated TA-Lib calls and does not recompute an
indicator for each threshold. All paths include loading, feature computation,
backtesting all requested metrics and compact result writes. The compiler does
not know indicator names, archived PnL or which candidate looks attractive.

The family scalar/NEON difference is small; the NEON median is slightly slower
in this final measurement. No standalone SIMD speedup is established here.
The gains come primarily from avoiding repeated complete history scans; real
NEON/AVX2 kernels remain tested paths, not a marketing explanation for all gains.

Matched feature work drops from 1,741 materialized nodes / 522 temporal passes
in direct evaluation to 408 materialized nodes / 228 temporal passes in the
family path, plus 500 separately counted fused pointwise nodes. This includes
22 grouped moment outputs, 211 recurrence lanes and 133 prepared-bank hits.
Materialized-node reductions do not mean the fused arithmetic disappeared.

A separate larger measured pair evaluates **1,050,704 complete
ten-metric sets**, from **1,040 requests / 1,027 distinct numerical roots**,
radius ten and 257 thresholds per direction. It uses the same history, costs,
metrics, native thread count and general evaluator. Thresholds are actual
parameters, not extra numerical features.

|---|---:|---:|

| Filang generic family path | 10.126915 s | 287.8 MiB |

This pair's measured ratio is **22.820x**. It is **one repetition**, not
a statistically established distribution of speedups. Every metric matches the
reference within the declared envelope, with trade/sample counts exact.

A predecessor run exhaustively compared all captured features and every threshold
mask against TA-Lib and all metric sets against the reference backtester. The final
price-prefix hoist changes scheduling only: **every byte** of both final captured
feature and metric files was compared with that externally verified predecessor,
and the final timed output was compared again against a fresh external run.
This chain is recorded in the benchmark and file checksums. Verification runs
and their captured-output cost are separate from the no-capture matched timings.
The predecessor's numerical/mask verification is retained, not overwritten.

## General machinery, not a special indicator benchmark

The compiler identifies shared **input/window/numerical-profile state**, not
catalog labels: paired moments, independent coefficient lanes, temporal materialization
boundaries and terminal pointwise tiles. Price prefixes/category terms are reused
across all programs. Full-risk threshold updates maintain chronological drawdown
and completed trade outcomes; no cheaper risk proxy is substituted.

Tests also feed anonymous nested atom programs and an actual corpus from Filang's
existing open generator through the same compiler. No historical result is
embedded in a kernel; there is no TA-Lib runtime call, benchmark-specific opcode,
reduced precision, hidden extra worker, or arbitrary omission of a metric.

The native APIs are reusable by open sweeps. The finite anchor/neighborhood runner
still writes one compact metric row per requested result and constructs its finite
catalog; it is **not the trillion-address scheduler**. The previously delivered
paged scheduler remains separate. Further integration and region compression must
be measured; neither a million readout/scenario cases nor this capability establishes
one trillion distinct-feature throughput. Bounded tiles and caches do not erase
output-proportional work or physical work for genuinely distinct programs.

## Reproduction and retained artifacts

Use the commands in `docs/ANCHOR_PARITY.md`. The final reusable local gate is
`runs/anchor-release/gate.txt`, bound to the executable above; rebuilds that change
that digest require a fresh parity run. Final local runs:

```text
runs/anchor-release
runs/anchor-release-reference
runs/anchor-release-bench
runs/anchor-release-million
```

The report retains source/data identities, expanded anchor manifest, all anchor
metric results, verification summary, gate, coverage inventory, repeated benchmark
measurements and raw process resource logs. Large captured histories and million-row
binary metrics stay under ignored `runs/`; `artifact_checksums.json` gives exact
sizes/digests. Deterministic macros and benchmark commands reproduce the larger
parameter domains without committing market data or enormous outputs.
