# Joint strategy-family sweeps — 2026-10-05

## What is delivered

Filang 0.7 adds a native joint rule-program layer over ordinary numerical graphs.
This is not ten independently scored indicators: one strategy jointly chooses
indicator/atom variants, comparison parameters, temporal qualifiers, and Boolean
connections. The same numerical bank, packed kernels and reversible full-risk
Executor are used. No Limen or Terasweep import, per-candidate Python callback,
individual-profitability shortlist, reduced precision or cheaper metric is required.

The first complete real-data campaign resolves **8,748,874,821,870
requested strategy/parameter addresses** through **9,037,698 exact
result boxes**. Every box's compound positions, coverage and ten backtest metrics
were independently verified. This is a completed trillion-address **restricted
parameter-family** evaluation, not trillions of independent numerical features,
globally unique strategies, or sequential full-ledger replays. Grid redundancy,
ordered slot aliases, and data-specific behavioral equivalence remain explicit.

## Fixed workload and counting

The protocol was recorded in issue #16 before the experiment. Ten known families:
SMA, EMA, RSI, MACD, Bollinger, stochastic, ATR, ROC, CCI, and rolling bar VWAP.
Each supplies the original atom construction and two predetermined neighbors:
principal period -1/source coefficient -.005/component mixture .05, and period
+1/source coefficient +.005/component mixture .05. The nine choices per family
are these three variants times plain/persist2/recent3 predicate qualifiers.
These are three coupled atom variants, **not** a dense independent sweep of every
internal atom coordinate.

Two ordered condition slots must choose different family tags. All AND, OR, and
AND-NOT templates are requested. Each condition's unchanged micro cutoff range
is refined to 20,001 rational-grid points. Thus:

```
10 * 9 ordered family pairs
* 9 * 9 variant/qualifier choices
* 3 Boolean templates
* 20001 * 20001 threshold coordinates
= 8,748,874,821,870 requested addresses.
```

The tags constrain the declared domain; they never choose an execution kernel.
Symmetric AND/OR slot assignments and identical realized behaviors are not called
independent strategies. Every declared address is covered; none is heuristically
pruned. No single-feature ranking decides which alternatives enter the joint search.

Pinned BTCUSDT four-hour data retain 10,602 input bars for numerical and
Boolean warmup. Only 2024-01-01 through 2025-01-01 exclusive is scored: 2,194
complete next-open execution intervals. All candidates pay **10 bps fees +10 bps
slippage per side**, remain cash-funded long/flat, and end flat. This is an
already-observed, in-sample systems/research experiment, not untouched validation,
a live fill/capacity result, or permission to place trades.

## Native capability and validity

Numerical expressions feed threshold and relative gt/ge/lt/le/eq/ne comparisons,
directional crossovers and slopes. Leaf predicates and arbitrary compound rules
support AND/OR/NOT, persistence, recency and onset. Rule templates must consume
every declared slot. Relative comparisons require matching units and use direct
comparison, not an overflow-prone subtraction rewrite.

Truth and validity are separate packed planes. AND and OR require both operands
valid; NOT complements only within validity. Persistence/recency require a full
valid input window. This is deliberately conservative validity, not SQL's
short-circuit three-valued OR. No source rows are dropped. Compound temporal
operations run over causal history before slicing the scored interval.

The shared context rejects mismatched Data instances, ranges, costs and unsupported
gap schedules. Public alternatives require unique IDs, complete nonoverlapping
cells, stable predicate validity, and correctly padded bits. Explicit tests cover
malformed inputs. Exact coordinate/metric equivalence under domain partitioning
is tested; it is not a durable checkpoint controller.

These categories are not interchangeable unique-feature counts. State calls plus
cache hits reconcile to the box count. Cache eviction can make a behavior recur;
there is no asserted global unique-position count.

Pointwise Boolean templates compile the final condition into two cofactors,
F0 and F1, giving `(F0 & !B) | (F1 & B)` at packed-bit granularity. Scalar, NEON,
and AVX2 implementations retain the same truth/validity semantics. Compound
temporal rule graphs use the declared general evaluation path, not an invalid
pointwise certificate. Leaf temporal qualifiers may still feed pointwise templates.

Adjacent final-axis cells are coalesced only after exact output-mask equality.
An optional bounded cache uses hashes only as an index, checking full words before
score reuse. Misses reach existing sparse execution-state updates or chronological
fallbacks. Different costs keep their own metric state. Numeric roots, predicates,
partial logical computations, and execution results are separate sharing layers.

**97.6148%** of addresses
have mixed position paths; 208,680,929,227 are all-flat. The captured run
has zero all-invested output boxes and zero constant-cofactor shortcuts. Hence the
large count is not solely a cash/always-long collapse, although threshold-region
compression is the main reason its logical count is far larger than physical work.

## Independent verification

The verifier reconstructs ordinary expressions using pinned TA-Lib/components,
checks every predicate truth/validity cell, enumerates every Cartesian predicate
cell, and verifies that each output box covers exactly identical positions and
that the boxes partition the entire requested domain. Every **9,037,698**
box is checked against independent sequential cash/share accounting, not Filang's
incremental tree. Trade/period counts and masks agree exactly; maximum absolute
metric discrepancy is **1.5916157281026244e-11**. There are an additional
182 systematically placed NumPy accounting checks, correctly
labeled a subset. The C oracle is verification-only and not a timing denominator.

The new numerical gate checks 30 baseline/endpoint programs under two cost
scenarios, including complete value, validity, trade and equity traces. The prior
88-case reference gate also passed on this final executable. Neither numerical
tolerances nor decision equality requirements were relaxed.

A separate **three-slot, 1,485-address control** combines relative EMA comparisons,
crossover, slope, inclusive/inequality thresholds, onset, and compound temporal
logic. All 664 output boxes passed independent coverage/position/metric checks.
The exported full-search best program was replayed as a singleton through the
ordinary expanded path; all ten metrics matched, max discrepancy 2.28e-13.

A clean cloned source tree passed **58 Rust tests**, formatting, warning-free
Clippy and a locked/offline release build. Tests include scalar/SIMD bit tails,
comparison/invalidity semantics, full two/three-slot metric parity, overflow and
context rejection, hash-collision checks, future append and partitioned replay.
Exact-final-head macOS/Ubuntu CI is required before merge; retained measured-source
CI already passed. Fresh build and test logs identify their precise commit.

## Measured performance

Apple M1 Max; one native worker; f64; Rust 1.63.0. OS caches were not flushed and
CPU affinity was not pinned. The user device is not an isolated benchmark host.
All repeated timings are fresh processes with rotated mode order; no independent
reference verifier ran concurrently with the timed comparisons.

A captured whole-process full run took **23.43 seconds**, maximum RSS
**42.40625 MiB**, including startup, data/gate loading, preparation, all requested
full-risk results, and **1,229,126,928 bytes** of result records plus predicate proof
and metadata. This is one captured run, not a latency guarantee. File output is
flushed through the normal OS interface, not an explicit durable-fsync benchmark.

The small matched workload has the same alternatives/templates but three cutoff
values per axis: **196,830 actual strategy addresses**. Every logical result was
expanded and compared across all five paths. The full workload compares every
box coordinate and all metrics across paths, without pretending to run an
unfactorized 8.75-trillion sequential reference.

| Execution path | Small domain median | Full domain median |
|---|---:|---:|
| Per-address native chronological replay | 5.613982s | Not run |
| Shared predicate cells, scalar rules, no cache | 0.901848s | 18.791524s |
| Boolean cofactors, scalar, no cache | 0.898221s | 14.344616s |
| Boolean cofactors, NEON, no cache | 0.868512s | 14.451086s |
| Boolean cofactors, NEON, bounded cache | 0.818495s | 14.830336s |

Three repetitions per path. Summary output is used for all timed comparisons:
all metric results are computed, but address-by-address and box-based result
encodings differ physically. Every timed hash matches its fully checked proof.
The small default-path gain is **6.859x**.
On the full workload scalar cofactor compilation is **1.310x**
over the already-factorized scalar-cell path. The default NEON/cache full path is
**1.267x** over that same baseline.
Do not multiply these ratios by previous release speedups or use independent
verification runtime as a denominator.

**Negative findings are retained:** full-workload NEON did not establish a gain
over scalar cofactors, and the cache was slower than no cache despite avoiding
millions of state calls. For the temporal control, per-address replay median was
0.182859s versus 0.133765s for scalar
cells and 0.139270s for the cached path.
The cache again adds overhead there. Backend and cache choices remain explicit;
no universal benefit is claimed for any one optimization.

The benchmark rechecks complete large proof files before deleting only its own
temporary copies, retaining hashes and comparisons. The independently verified
source run is retained. This avoids gigabytes of redundant proof files on the
user's nearly full disk. It does not skip result calculation or parity checking.
