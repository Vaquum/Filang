# g1 radius protocol

## A1. Exact queries retain their existing path

Use the same machine, toolchain, pinned recording and prepared geometry
widths for the existing engine and the radius candidate. Test one- and
two-bar price keys, a two-bar all-axis key, and a wider chained key.
For the Study binding also test recorded and chained price and dimension
questions with explicit and omitted radius zero. Require equal keys,
chronological positions, tri-valued classifications and byte-identical
Study replies. Existing count calls and explicit zero must select the
same exact operation and return the same bytes.

Use five alternating fresh processes per build. Read a loaded tape,
warm the indices, and report pooled median latency. Allow a 5% median
measurement band for an unchanged exact call path. Separate positive
radius timings and report observed keys, not declared domain size. Check
the reference half-flip cost independently, including directions and
the signed zero comparisons. Enumerate small observed domains and
check nesting, projections, ties and zero-radius identity.

## A2. Integrated Query and Composer replication

Repeat A1 against the same baseline and recording with the Query
control and Composer matching integrated. Use the identical five
paired processes, four prepared keys, repetitions, byte checks and
5% timing band. Verify the Query control in Chrome with the two-bar
pinned shape. Check Composer's dimension-aware windows against the
shared radius vectors, and rerun its eleven worker timing scenarios
on the same five real histories.

## A3. Preserve direct dispatch for exact counts

A2 exceeded the 5% timing band for one bar. Move the existing exact
count operation into the early dispatch path, keeping its parser,
prepared index and response the same. Repeat the five paired processes,
four keys, byte checks and 5% criterion. Retain the A2 result whether
or not this attempt improves it.

## A4. Isolate radius from the merged prerequisites

A3 still missed the one-bar band with the older baseline. Compare the
radius candidate with the same Query, Composer and adaptive-postings
prerequisites compiled without radius. This comparison isolates the cost
of radius from the larger command dispatch changes. Retain the earlier
samples, byte checks, five paired processes and 5% criterion.
