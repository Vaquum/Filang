## Independent verification: explicit limits

Three complementary checks are retained, and MUST NOT be conflated:

1. **Exhaustive predicate checks at every density.** Independent TA-Lib/component
   numerical formulas reconstruct every atom construction, its qualifiers, all
   threshold transitions, truth/validity masks, exact multiplicities and first
   coordinates. Every streamed membership is checked, including all 4,305,671
   memberships at full density. No mask disagreements. Unmodified full histories
   additionally passed the 30-program/60-scenario reference gate.
2. **Complete large-run coverage replay plus checkpoint metric checks.** A separate
   C Boolean set implementation reconstructs the entire sorted product-tree
   partition. All task ranges, node visits, leaf/nonleaf counts, signature-pair
   coverage and weighted logical coverage match. All checkpoint files and the
   canonical result digest reconcile. Separate sequential cash/share accounting
   checks EVERY retained task winner: 2,052 / 3,888 / 6,048 ledgers, respectively,
   with systematic NumPy checks. Maximum metric discrepancy is about 1.01e-11.
   This does NOT independently replay every metric evaluated in the large runs.
   Summary mode retains per-task result hashes, not each of the 2.1 billion
   metric records. Hashes demonstrate artifact integrity, not independent
   numerical correctness of those unretained values.
3. **Exhaustive captured-domain metric parity.** Three explicit smaller domains
   retain every result. Independent product-mask certificates, nonoverlapping
   coverage and sequential cash/share accounting check all 10,398,130 resulting
   metric regions. Leaf-only output additionally agrees at all 13,268,118 leaf
   metric records. The two-family small domain is expanded through the ordinary
   pre-dense joint engine, comparing all 354,294 requested strategy results.
   The ten-family captured domain spans 15,943,230 requests; the three-family
   21-cutoff domain spans 52,081,218 requests. These are not the full 41-point
   large grid. Maximum captured metric discrepancy is about 1.60e-11.

Trade/period counts remain exact; numerical tolerances are unchanged. C sources
are verification-only, neither runtime dependencies nor timing denominators.
Large-run verification is intentionally scoped: it is wrong to describe this
as exhaustive independent replay of every full-density metric. The underlying
numerical and execution kernels also retain their prior reference tests.

## Reproduce

The synchronized runtime uses the same data/gate-qualified native engine as the
previous joint and micro paths. Example (fresh output paths required):

```sh
./target/release/filang dense-example --out runs/my-dense41.cfg --coefficients 41
./target/release/filang dense-inspect --config runs/my-dense41.cfg
./target/release/filang dense-sweep --config runs/my-dense41.cfg \
  --gate runs/dense-v08-final-parity/gate.txt --out runs/my-dense41 --workers 4
.venv/bin/python scripts/verify_dense.py --run runs/my-dense41 --workers 4
```

The last command performs all memberships/product coverage and task-winner
metric checks; it does NOT claim all large-region metric replay. Native summary
mode computes all requested full metrics, retaining per-task digests and winners.
The recorded full result directory is `runs/dense-v08-final-41`; the coarse and
intermediate results use suffixes `-3` and `-11`. Gate bindings must be refreshed
when code/data changes; no bypass is provided. Begin with the existing
cohort-parity command and independent cohort_reference.py check for a new binary.

To reproduce the independently captured matched controls and benchmark:

```sh
.venv/bin/python scripts/prepare_dense_controls.py --out runs/my-dense-controls \
  --gate runs/dense-v08-final-parity/gate.txt
.venv/bin/python scripts/benchmark_dense.py --proof-root runs/my-dense-controls \
  --gate runs/dense-v08-final-parity/gate.txt --out runs/my-dense-times --repeats 3
.venv/bin/python scripts/check_dense_resume.py \
  --config runs/my-dense-controls/small.cfg --reference runs/my-dense-controls/proof-small \
  --gate runs/dense-v08-final-parity/gate.txt --out runs/my-dense-restart
```

Use `--max-tasks N` for a deliberate pause, then the same domain/output with
`--resume true`; worker count may change. Backend/code/data/contract changes
invalidate the stored context. `--certificates false` is the leaf-pair ablation.
Capture writes full metric-region files and can be very large: never enable
it blindly for the two-billion-region campaign. Its complete 128-byte output
would be roughly 269 GB, before additional artifacts.

The native semantic tests, independently captured controls, checksum/corruption
checks and fresh-clone locked/offline build are retained. Compiler tests cover
generic anonymous predicates and invalid/tied/temporal inputs, not just named
indicators. Public dense source currently exposes this ten-family pointwise
pair domain; arbitrary spill-backed catalogs, distributed/adaptive controllers,
more-than-two dense conditions and compound-temporal trillion throughput remain
outside this delivery. Walk-forward transfer of joint tuning is a separate
research question, not established by an in-sample systems campaign.
